# Contributing

Thank you for helping keep this survey accurate and current. Four kinds of contribution are welcome, each with an issue template; a pull request that follows the same fields works too.

The golden rule: **edit the data, not the generated files.** `index.html`, `README.md`, `data/references.bib`, `data/exports/*` and `paper/references.bib` are generated by `python3 scripts/build.py`.

## add-paper

Suggest a study for the review. Please give:

- the canonical link (arXiv abstract, DOI or proceedings page) and the version you read;
- its relationship to Jev — evaluates hosted Jev, builds or evaluates an independent Jev-like model, uses typed decisions inside a system, or adjacent background;
- the task, data and baselines; the main result **with its locator** (section, table or figure);
- limitations the authors state, and whether code, weights, data or raw predictions are public.

Inclusion as **core** requires that the study evaluates TypeSafe Jev, a clearly identified Jev-like typed-decision implementation, or a system whose contribution materially depends on such decisions. Name matches (Japanese encephalitis, JEPA, unrelated “TypeSafe” uses, other meanings of RLCD) are excluded. Adjacent methods may enter as background with a stated role.

## correction

Report a wrong number, locator, version, date, availability status or relationship. Link the exact source location. Corrections that change a count must also update `CHANGELOG.md`.

## resource-update

Report a new release, commit, licence or availability change for an open model, benchmark, application or tool. Pin the commit you read. Record availability per field (`code`, `weights`, `training_code`, `inference_code`, `evaluation`, `data`, `raw_predictions`). “Not located” is not “does not exist”.

## reproduction

Report a rerun of a published result. Include the protocol, model versions or checkpoints, hardware, dates, raw outputs and scripts, and state what differed from the original. A claim’s `independently_reproduced` field only turns true when a public run log is linked.

## Editing the data

1. Edit `data/papers.json`, `data/claims.json`, `data/repositories.json`, `data/taxonomy.json` or `data/review-relations.json`. The vocabularies live in `data/taxonomy.json`; `data/README.md` documents every field.
2. Keep unknown values `null` **with a reason** (`not_reported`, `not_checked`, `not_accessible`, …). `null` is never zero.
3. Keep evidence types apart: author-reported experiments, vendor documentation, vendor-reported results, community reports and code/README inspection.
4. Keep measurement scopes apart: single request, amortized per question, batch, end to end, simulation, author estimate, vendor claim.
5. Run:

```sh
python3 scripts/validate-data.py
python3 scripts/build.py
python3 -m unittest discover -s tests
```

6. For new literature, run `python3 scripts/update-metadata.py` (and `scripts/update-github.py`). They write a local working folder under `research/increments/` (not committed) with only the records not screened before. Record each decision and reason in `research/screening.json`, add included records to `data/`, and log the run in `data/search-runs.json`.
7. Push to `main`: CI validates and rebuilds, and GitHub Pages republishes the site. The manuscript PDF is rebuilt with `python3 scripts/build-paper.py --pdf` (needs matplotlib and TeX Live with XeLaTeX).

## Style

Report numbers with their denominators, versions and scope. Avoid rankings across heterogeneous tasks, promotional adjectives and priority claims (“first”, “best”) unless a source establishes them. Credit prior work, including work that overlaps with this survey.
